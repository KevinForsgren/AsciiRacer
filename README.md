# AsciiRacer

AsciiRacer is a C++23 terminal racing game rendered with ANSI escape sequences and Unicode/ASCII artwork. Steer a car through three lanes, avoid incoming traffic and track edges, collect fuel and tyre pickups, and keep the vehicle running long enough to improve the high score.

## Features

- Alternate-screen terminal rendering so gameplay does not permanently fill the shell.
- Non-blocking raw keyboard input for responsive controls.
- Easy, medium, and hard difficulty settings with different movement and degradation rates.
- Scrolling roadside environment, coloured player/enemy cars, telemetry, score screen, and persistent high score.
- Cross-platform terminal handling for Linux and Windows implementations in `src/terminal.cpp`.

## Requirements

- CMake 4.3 or newer.
- A C++ compiler with C++23 support.
- A terminal that supports ANSI escape sequences, true-colour sequences, and the Unicode glyphs used by the artwork.

## Build and run

From the repository root:

```bash
cmake -S . -B build
cmake --build build
./build/AsciiRacer
```

On Windows, run `build\AsciiRacer.exe` (or the equivalent executable generated by the selected CMake generator).

The game creates `data.dat` in the working directory to store the binary high score. The file is created automatically if it does not exist.

## Controls

| Screen | Key | Action |
| --- | --- | --- |
| Main menu | `R` | Start a race and choose difficulty |
| Main menu | `S` | Open the scoreboard |
| Main menu | `Q` | Quit |
| Difficulty | `E` | Easy |
| Difficulty | `M` | Medium |
| Difficulty | `H` | Hard |
| Gameplay | `A` | Move left |
| Gameplay | `D` | Move right |
| Scoreboard | `H` | Return to the main menu |

## Gameplay

The race ends when the player hits incoming traffic or the track edge, or when fuel, tyre health, or chassis health reaches zero. Fuel and tyre pickups restore their corresponding resource and award points. The telemetry panel displays race time, score, high score, and current vehicle status.

For the best layout, use a terminal wide and tall enough to display the track, telemetry panel, and controls without clipping. The game reads the terminal size every frame, but very small windows cannot display the complete interface.

## Project layout

```text
src/
├── main.cpp             Game loop, input handling, traffic, and score persistence
├── render.cpp           Menus, track, car, telemetry, and score rendering
├── cars.cpp             Player/enemy car state, movement, and collision checks
├── environment.cpp      Collectors and scrolling roadside objects
└── header/
    ├── AsciiArt.h       Sprites and static screen artwork
    ├── cars.h           Car and traffic types
    ├── environment.h    Collector and ground-system types
    ├── gameSettings.h   Shared game-state structures
    ├── render.h         Rendering API
    └── terminal.h       Terminal-control API
```

## Architecture

The main loop owns game state and coordinates input, simulation, and output. Rendering functions return strings containing cursor-position and colour escape sequences, while `TerminalControl` isolates platform-specific terminal operations. Car and environment classes manage simulation state independently from the screen layout.
